- To execute a program, you need few things
	1. *Main memory* - place where instructions and data are stored
	2. *System bus* - way for instructions/data to travel between memory and processor
	3. *Processor* - element of system that executes instructions
### Processor
- *CPU* - brains of computer
	- Fetches instructions from memory via bus, decodes instruction, and executes it
		- Repeats until program is finished
- Different steps can be executed in parallel
	- One instruction is executed, another is decoded, and another is fetched
	- Called *pipeline*
- *Word* - largest unit on processor
	- 64-bit processor has word size 64 bits
- CPU instructions are specific to processor
	- Some operations are only in "supervisor mode" and not "user mode"
		- Attempting to run supervisor operations in user mode results in error
- *Registers* - storage locations of CPU
	- Can store data/instructions
	- Management is done by OS
	- Holds key variables/temporary results
	- Word-sized
### Interrupts
- Signal to processor requiring immediate attention
- Can come from many sources
	- *Program* - something happens in program
	- *Timer* - configured timer within processor time expires
	- *Input/Output* - I/O controller signals (un)successful completion of operation
	- *Hardware Failure*
- Improves processor utilization
	- CPU should always be doing something
- Can be ignored, but it is rare
	- Want to always *handle* (deal with) it
- OS is responsible for storing state of program being interrupted, handling interrupt, and restoring state of program that was interrupted
- Multiple interrupts can happen in short period of time
	- Interrupts can be suspended

- *Storing/Restoring State* - state of CPU is stored
	- Values of registers are stored by pushing them on stack
	- When interrupt is finished, values are popped off stack and loaded into registers again
	- Program execution continues as though interrupt never happened
- *Multiprogramming* - matter of scheduling, and is out of our control for application programming

### Trap
- Interrupts are generated by hardware and in software
	- In software, it is called a *Trap/exception*
		- Generated by error or user program request
- If generated by error:
	- OS will send the exception to program that caused it, which is fatal to program
		- Can deal with it with exception
- If requested:
	- It is getting the OS attention
- *Supervisor (Kernel) mode* - allows all instructions/operations
	- Reading from disk
	- Writing to console output
- Processors keep track of mode with mode bit
	- Computer starts in kernel mode
	- User programs always start in user mode
	- When trap/interrupt happens, mode bit is kernel mode
		- When it finishes, it goes back to user mode

#### Motivation for Dual Mode
- Protect system and integrity against bad users
	- Example: program's butting in line
- Trade-off is performance, as switching between modes requires instructions and time
